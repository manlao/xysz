# 取价与交易规则

## 一、时段划分

先判断是否交易日（`today ∈ get_calendar()`），再按当前时间落阶段。

### 三个时间概念（勿混）

| 概念 | 时段 | 含义 |
|---|---|---|
| **撮合时段** | **9:30–11:30 / 13:00–15:00** | 委托实际撮合成交的时间窗 |
| **午间休市** | 11:30–13:00 | **可挂单、可撤单**，但均不立即撮合/处理，13:00 后才生效 |
| **盘前** | 09:15 之前 | 尚未进入委托受理窗口 |

> 09:15 是**取价参数的下界**（快照数据从 09:15 起才有），不是交易时段起点；真正的交易时段起点是 **9:30**。

### 时段表

| 阶段 | 时间区间 | 可否下单 | 可否撤单 | 取价路径 |
|---|---|---|---|---|
| 盘前 | 00:00 – 09:15 | ✗（`-1031`） | ✗（`-1650`） | 最近完成交易日收盘价 |
| 早盘前段 | 09:15 – 09:30 | ✗（`-1031`） | ✗（`-1650`） | 当日快照最新价 |
| 上午连续竞价 | 09:30 – 11:30 | ✓ 可撮合 | ✓ 立即处理 | 当日快照最新价 |
| 午间休市 | 11:30 – 13:00 | ✓ **收单不撮合**，13:00 后撮合 | ✓ **受理撤单，13:00 后才处理** | 上午收盘最新价 |
| 下午连续竞价 | 13:00 – 15:00 | ✓ 可撮合 | ✓ 立即处理 | 当日快照最新价 |
| 盘后至结算 | 15:00 – 16:30 | ✗（`-1031`） | ✗ | 最近完成交易日收盘价 |
| 盘后结算后 | 16:30 – 17:00 | ✗（`-1031`） | ✗ | 同上 |
| 盘后清算后 | 17:00 – 17:30 | ✗（`-1031`） | ✗ | 同上 |
| 盘后分红后 | 17:30 之后 | ✗（`-1031`） | ✗ | 同上 |
| 非交易日 | 周末与法定休市 | ✗（`-1082`） | ✗ | 最近交易日收盘价 |

> ⚠️ **盘后不能下单（文档与实测冲突，以实测为准）**
>
> 规则文档 2.1 节写「下午收盘后到次日早上 9:30 期间可提交委托，会到次日开盘按规则撮合成交」，**但这一条在柜台实测中不成立**：盘后时段下单被柜台直接拒绝，返回 `-1031 非交易时段不能下单`，**并未受理为隔夜委托**（已核对委托表，无该笔记录）。
>
> 实现与预期管理：
> - 不要向用户承诺盘后可以挂单或「夜间委托次日自动成交」；
> - 盘后提交委托会被柜台拒绝，错误码为 `-1031`，本技能会如实提示「非交易时段不能下单（错误码 -1031）」；
> - 如需隔夜生效，只能在交易时段内下单。

> **午休撤单的处理时点**：午间休市期间提交的撤单请求**会被受理，但不会立即处理**，要到 13:00 开盘后才实际生效。因此午休撤单后，委托状态在开盘前仍可能显示为 `New`（而非 `Cancelled`），这是正常现象，不要据此判断撤单失败。

## 二、快照取价回退链

### 增量序列（三角数）

```
1, 3, 6, 10, 15, 21, 28, 36, 45, 55, 66, 78, 91, 105, 120 ... 406
↑ 每次递增 1, 2, 3, 4, 5, 6 ...
共 28 档，最远回溯 406 分钟（约 6.8 小时），
确保 09:15 → 15:00 全时段都能一路回溯到开盘，不会中途断掉
```

### 路径 A：连续竞价

```
end_time = 153100000        # 固定当日 15:31:00
begin    = now - 1min，然后按序列向前回退
下界     = 09:15:00
```

### 路径 B：午间休市

```
end_time = 113100000        # 固定 11:31:00
begin    = 11:29，按序列向前回退
下界     = 09:15:00
```

命中后取最后一条快照的 `last`（最新价），并标注来源为「午间休市·上午收盘最新价」。

### 时间戳格式（关键）

`begin_time` / `end_time` **必须是 8 或 9 位**（时分秒毫秒）：

| 写法 | 结果 |
|---|---|
| `105500000`（9 位） | ✓ 正确 |
| `105500`（6 位） | ✗ **静默返回 0 行，不报错** |

### 快照返回结构（关键）

`query_snapshot` 返回 `{日期str: {代码: DataFrame}}`，**两层字典**：

```python
snap = md.query_snapshot(['600***.SH'], begin_date=20260101, end_date=20260101,
                         begin_time=110000000, end_time=113100000)
row = snap['20260101']['600***.SH'].iloc[-1]   # ← 两层
row['last'], row['ask_price1'], row['bid_price1'], row['pre_close']
```

### 无行情处理

回退链走完（begin 已早于 09:15）仍无数据 → **报「无行情，不能下单」**。

**绝不用 0 或前收盘价顶替。**

## 三、非交易时段取价

```
1. 若今天是交易日但处于盘前/盘中/午休 → 当日日线尚未生成
2. 从交易日历取 < today 的最大交易日 → target
3. query_kline([code], target, target, Period.day) 取 close
4. 若为 None（数据缺失），再往前取，最多回退 5 个交易日
5. 全部失败 → 报「无行情，不能下单」
```

> 注意：盘中当日日线**尚未生成**，直接取当日会得到空结果。

## 四、限价委托价格上下限

⚠️ 与「涨跌幅限制」是**两套不同的约束**，不可混用。

### 涨跌幅限制（提交委托的总体约束）

| 品种 | 比例 |
|---|---|
| 科创板、创业板股票 | 20% |
| 非科创板非创业板股票、ETF基金 | 10% |

`涨跌幅价 = 前收盘价 × (1 ± 比例)`，四舍五入取至最小变动单位。

### 限价上下限（柜台实际比对的边界）

由**基准价**计算，基准价取自**盘口**，不是前收盘价。

| 板块 | 上限 | 下限 |
|---|---|---|
| 上海主板、深圳主板、创业板 | `max(买入基准价 × 102%, 买入基准价 + 10 个最小变动单位)` | `min(卖出基准价 × 98%, 卖出基准价 − 10 个最小变动单位)` |
| 科创板 | `买入基准价 × 102%` | `卖出基准价 × 98%` |

### 基准价取值顺序

| 类型 | 取值顺序（取第一个有效值） |
|---|---|
| 买入基准价 | 卖一价 → 买一价 → 最新价 → 昨收 |
| 卖出基准价 | 买一价 → 卖一价 → 最新价 → 昨收 |

若四档全部取不到（盘前无盘口），**跳过上下限校验**，交由柜台判断。

## 五、交易单位与最小价位

### 交易单位

| 品种 | 申报数量要求 | 卖出零股处理 |
|---|---|---|
| 普通A股（非科创板）、ETF基金 | 100 股（份）或其整数倍 | 余额不足 100 股的部分，**一次性申报卖出** |
| 科创板 | **大于 200 股**，数量为整数 | 余额不足 200 股的部分，一次性申报卖出 |

### 最小价位

- A 股：**0.01**
- ETF 基金：**0.001**

### 上市初期限制

以下时段**不接受委托**：

- 科创板、创业板股票上市前五天
- 非科创板非创业板 A 股上市第一天
- 股票暂停上市后恢复上市第一天
- 股票退市后重新上市第一天

## 六、撮合规则

限价委托，**模拟撮合，没有量的限制**。

| 方向 | 成交条件 | 成交价 |
|---|---|---|
| 买入 | 委托价 ≥ 卖一价 | **最新价，全部成交** |
| 卖出 | 委托卖出价 ≤ 买一价 | **最新价，全部成交** |

即价格满足条件即全部成交，本环境基本不会出现部分成交（`PartiallyFilled` 罕见）。理解这一点有助于解读成交与委托记录，但**不必在报告或下单提示中向客户强调撮合机制**，仅需客观展示成交数据。

---

## 七、交割与权益

- **T+1 交割**：沪深京 A 股、场内基金（ETF）、科创板、创业板均为 T+1，当日买入当日不可卖出。
- 送股、除权、分红派息、份额拆分：符合条件的统一在**除权除息前一天盘后结算时**到账，**不扣减股息红利税**。

## 八、盘后生命周期

| 开始时间 | 阶段 | 柜台动作 | 查询影响 |
|---|---|---|---|
| 16:30 | **盘后结算** | 针对当天的交易进行**可用划转**；**未成交的进行撤单释放资金** | 未成交单变为 `Cancelled`，冻结资金已释放 |
| 17:00 | **盘后清算** | **当日委托、成交转成历史后清空当日委托与成交** | 不带日期查 `order`/`trade` **返回空表** |
| 17:30 | **盘后分红** | 处理分红送转 | 除权后持仓成本价与市值变化 |

### 典型踩坑

收盘后（15:00–17:00）查当日委托看到空结果，**不是 bug**，是数据已转为历史。

**17:00 后不带日期查询时，本技能会主动提示**：

> 当前已过盘后清算时间（17:00），当日委托与成交已转为历史并清空。如需查看，请用 `--begin` / `--end` 指定日期区间。

`query_position` 查的是**当日持仓**，不受清算影响（持仓跨日延续），但持仓的 `init_qty`（日初持仓）在跨日后才有意义。

## 九、下单风控阈值

### 一级 · 硬拦截（拒绝并给中文原因）

| 校验 | 规则 |
|---|---|
| 代码格式 | 必须 `代码.市场`，后缀仅 SH/SZ/BJ 且与代码段匹配 |
| 交易单位 | 按板块分支（见第五节） |
| 最小价位 | 按品种取 0.01 / 0.001 |
| 限价上下限 | 按第四节计算，越界即拒 |
| 资金 | 买入查 `query_max_qty` |
| 持仓 | 卖出查 `available_qty` |

**卖出失败的三种区分**（都不可卖，但原因不同）：

| 情况 | 判定 | 提示 |
|---|---|---|
| 无该标的持仓 | 持仓表查不到 | 「卖出查无持仓」 |
| T+1 锁定 | `available_qty=0` 且 `stock_sale=0` | 「持仓 N 股全部处于 T+1 锁定，当日买入当日不可卖出，最早可卖日为下一交易日」 |
| 卖出冻结 | `available_qty=0` 且 `stock_sale>0` | 「持股 N 股全部处于卖出冻结，可用 0 股，请先撤销在途的卖出委托」 |
| 可用不足 | `volume > available_qty` | 「可用 N 股（总持股 M 股，其中 K 股卖出冻结）」 |

### 二级 · 需显式确认

| 触发条件 | 判定依据 |
|---|---|
| 单笔 ≥ 账户总资产 50% | `price × volume` vs `query_asset().total_asset`（查询结果复用，不重复请求） |
| 单笔 ≥ 50 万元 | 绝对金额阈值 |
| 数量 ≥ 100000 股 | 数量阈值 |
| 卖出全部持仓 | `volume >= available_qty` |

二级确认下**只打印计划，不下单**；需追加 `--confirm` 才提交。

## 十、组合规则

- **每个用户最多只能建 1 个组合**（后台限制）。建过之后无法再新建，超出返回 `10006`。
- 若组合已存在，直接在该组合上操作即可。
- 组合名称 1~50 字符，同用户下唯一。
- 单次只能建**一个**组合。
- 初始资金本技能固定 100 万，不可自定义。
